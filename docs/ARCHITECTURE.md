# 아키텍처

~~~mermaid
flowchart TD
    Input["카메라 · 영상 · Mock"] --> Detect["프레임 획득 · 객체 검출"]
    Detect --> Policy["추적 · ROI · 체류 · 상태 전환"]
    Policy --> Output["공용 출력 우선순위"]
    Output --> Serial["Arduino LED · 음향"]
    Output --> Store["SQLite · 이벤트 영상"]
    Store --> Cloud["클라우드 재전송"]
    Policy --> Dash["관리자 화면"]
    Serial --> PIR["PIR · 출력 응답"]
    PIR --> Detect
~~~

카메라 캡처 스레드는 한 장짜리 최신 프레임 슬롯을 갱신합니다. 판단 루프는 대기 중 저주기로 추론하고, PIR 신호나 활성 트랙이 있으면 추론 주기를 높입니다. 영상 파일은 재생 시간, Mock은 가상 시간, 카메라는 monotonic 타임스탬프를 사용합니다. SQLite의 발생 시각은 별도 UTC입니다.

Arduino 통신, 영상 파일 인코딩, HTTP 동기화는 각자 작업 스레드를 사용합니다. 정책 이벤트와 출력 명령, ACK 결과는 명령 ID로 연결됩니다. 앱의 현재 출력은 정책이 요청한 값이고 Arduino 상태는 최근 응답으로 받은 장치 보고값입니다. 카메라 읽기가 끊기면 재연결을 시도하며, 마지막 프레임이 지정 시간보다 오래되면 보호 상태를 초기화합니다. Arduino에도 별도의 통신 타임아웃이 있습니다.

캡처 슬롯은 1장, 탐지·추적은 최대 64개, 시간 통계는 항목별 최근 512개입니다. 녹화는 저해상도 JPEG 사전 버퍼와 제한된 쓰기 큐를 사용합니다. SQLite는 WAL과 보존 일수·레코드 한도를 사용하며, 영상 파일과 로그에는 각각 디스크 보존 한도가 있습니다. 실행 중 이벤트 저장에 실패하면 로그와 대시보드에 오류를 남긴 뒤 감시를 계속합니다. 시작 시 DB 개방에 실패하면 경로와 권한을 확인합니다.

Jetson의 설치 의존성을 줄이기 위해 클래스별 IoU와 중심·속도 기반 매칭을 사용합니다. 긴 가림이나 같은 클래스가 교차할 때 ID가 새로 할당될 수 있습니다.
